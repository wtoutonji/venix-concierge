# Pagination

## Purpose

Provide a consistent server-rendered Teelya presentation layer around native WordPress pagination without reproducing pagination URL or query logic.

## Category and lifecycle

* Category: Structural
* Status: Experimental
* Introduced: Teelya 1.1.0

The API is available for controlled v1.1 use and may be refined before the component becomes Stable.

## Supported contexts

Using the global query supports normal WordPress paginated listing contexts:

* posts index;
* category, tag, and custom taxonomy archives;
* author and date archives;
* public custom post type archives;
* search results.

An explicit `WP_Query` can be supplied for a custom loop. The component renders nothing when the selected query has zero or one page of results.

## Markup

The component renders a labelled `<nav>` containing an unordered list. Each list item contains markup generated by `paginate_links()`. WordPress provides real link URLs, `prev` and `next` classes, and a non-link current-page element with `aria-current="page"`.

Teelya provides these stable structural classes:

```text
tly-pagination
tly-pagination__list
tly-pagination__item
```

The generated controls retain WordPress's native `page-numbers`, `current`, `prev`, and `next` classes.

## API and defaults

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `query` | `WP_Query` | Global `$wp_query` | Query whose `max_num_pages` and current `paged` value are used. |
| `mid_size` | `int` | `1` | Page links shown on each side of the current page. Negative values become zero. |
| `end_size` | `int` | `1` | Page links shown at each end. Negative values become zero. |
| `prev_text` | `string` | Translated `Previous` | Visible previous-page link text. Empty values use the default. |
| `next_text` | `string` | Translated `Next` | Visible next-page link text. Empty values use the default. |
| `aria_label` | `string` | Translated `Posts navigation` | Accessible navigation landmark label. Empty values use the default. |

The text arguments are plain text. HTML is stripped so previous and next controls cannot become icon-only through this API.

## Default/global query usage

```php
get_template_part( 'template-parts/components/pagination/pagination' );
```

The component reads the global query without changing it. WordPress supplies the pagination destinations through `paginate_links()`.

## Custom query usage

Pass the same paged value used to construct the custom query:

```php
$paged = max( 1, (int) get_query_var( 'paged' ) );
$query = new WP_Query(
	array(
		'post_type'      => 'post',
		'posts_per_page' => 6,
		'paged'          => $paged,
	)
);

if ( $query->have_posts() ) {
	while ( $query->have_posts() ) {
		$query->the_post();
		// Render the loop item.
	}
}

get_template_part(
	'template-parts/components/pagination/pagination',
	null,
	array(
		'query' => $query,
	)
);

wp_reset_postdata();
```

The caller owns the custom loop and its post-data reset. Pagination reads the query but does not mutate it or run an additional query.

## Accessibility

* The `<nav>` landmark has a translated, customizable accessible name.
* Native list semantics communicate the set of pagination choices.
* WordPress exposes the current page through a non-link element with `aria-current="page"`.
* Previous and next links use meaningful visible text rather than icons alone.
* Real anchors preserve native keyboard, focus, link-target, and no-CSS behavior.
* No focus management or JavaScript-specific keyboard behavior is required.

## Responsive behavior

The unstyled semantic list remains usable at narrow widths and cannot create a horizontal layout overflow. Derived projects may use wrapping and logical gaps when adding conditional component CSS. The `mid_size` and `end_size` arguments control large link sets without client-side collapsing.

## Assets

Pagination has no component CSS or JavaScript. It adds no frontend requests, has no motion, and remains understandable without CSS. Any downstream stylesheet must use the documented Teelya classes, load only with the component, and consume the Teelya design-token hierarchy.

## Dependencies

* WordPress `WP_Query`
* WordPress `paginate_links()`
* No other Teelya component
* No third-party dependency

## Extension points

No Teelya-specific filter is added. Projects can use the component arguments and WordPress's native pagination filters without depending on unstable component internals.

## Examples

Customize the visible controls and link range:

```php
get_template_part(
	'template-parts/components/pagination/pagination',
	null,
	array(
		'mid_size'  => 2,
		'end_size'  => 1,
		'prev_text' => __( 'Newer posts', 'venix-concierge' ),
		'next_text' => __( 'Older posts', 'venix-concierge' ),
	)
);
```

## Known limitations

* A custom query must receive the appropriate `paged` value when it is constructed.
* Multiple independently paginated loops on one URL require project-specific query variables and URL handling beyond this presentation component.
* The component intentionally provides no default horizontal layout or visual styling.
