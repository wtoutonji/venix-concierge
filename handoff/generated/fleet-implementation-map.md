- **EN/PL use the same vehicle structure**, ids, order, media-slot keys and image counts; only copy and the alt-text defaults differ per language.

## V-Class Extra Long removal (this pass)

- Removed as a Fleet-page vehicle on both `/fleet/` and `/pl/fleet/`: no section, no empty slot, no orphaned media or spacer remains. `theme/venix-concierge/inc/content/fleet.php` no longer has a `vclassxl` entry in `vehicles`; `fleet.v_class_extra_long.exterior` is removed from the theme media slots (`inc/media.php`) and from the Fleet page-content schema's `media` map (`project-core/.../schema-fleet.php`).
- **Index preserved, not reassigned:** Fleet's `vehicles` content array and the matching editor schema keep each remaining vehicle at its original array position — `0` S-Class, `1` E-Class, `2` V-Class, `4` Sprinter. Position `3` (formerly V-Class Extra Long) is simply retired. This means a page-meta override previously saved for Sprinter at `vehicles.4.*` still resolves to Sprinter; no remaining vehicle's saved text can shift onto another vehicle. The sanitizer (`venix_concierge_core_sanitize_page_content()`) only reads fields the current schema defines, so any stale `vehicles.3.*` or `fleet.v_class_extra_long.exterior` values left in an existing `_venix_page_content` row are silently ignored on next read and dropped on next save — no admin-visible V-Class Extra Long fields remain.
- The `vclassxl` capacity record in `venix_concierge_fleet_capacity_data()` / Venix → Fleet Capacities is **kept** for backward compatibility, per instruction; it has no Fleet-page or Home vehicle rendering it anymore.

## Final intentional overrides of the canonical `Fleet.dc.html`

`handoff/pages/Fleet.dc.html` is unchanged; production deliberately differs as follows.

- **Interior image pairs:** at 481px and wider the two interior images stay in 2 columns; at **480px and below** they stack one image per row. The vertical gap is **24px** in both layouts.
- **Focus ring:** the global focus ring remains 2px with a 3px offset; no Fleet-specific override.
- **Capacity:** the `[Confirm passenger & luggage capacity]` text placeholders are replaced by the shared passenger/luggage icon component (below).

## Capacity component

- **Data source (edit in WordPress Admin when values arrive):** Venix → Fleet Capacities, stored in the global option `venix_fleet_capacities` (owned by `project-core`, `inc/fleet-capacities.php`) keyed by vehicle id: `sclass`, `eclass`, `vclass`, `vclassxl`, `sprinter`. Each entry is `passengers` and `luggage` (whole number ≥ 1, or `null` when blank). `venix_concierge_fleet_capacity_data()` in `inc/content/fleet.php` returns the saved value, else the `null` default. Values are global, not per language and not in page meta; currently **`null` for every vehicle**. `vclassxl` is kept in this list for backward compatibility only — no Fleet-page or Home vehicle uses it since V-Class Extra Long was removed as a Fleet-page vehicle.
- **Rendering:** `venix_concierge_vehicle_capacity()` builds display items. A missing value renders **`TBC`** in English and **`Do potw.`** in Polish; labels are `Passengers`/`Pasażerowie` and `Luggage`/`Bagaż` (screen-reader text; the icons are decorative).
- **Shared component:** `template-parts/components/capacity/capacity.php` (argument: `vehicle` id) with `assets/css/components/capacity.css`.
- **Used on:** Home Fleet (four cards: S-Class, E-Class, V-Class, Sprinter) and the Fleet page (its same four vehicles). `assets/css/components/capacity.css` is enqueued only for the front page and the Fleet page.
- **Status:** passenger/luggage numbers are **unconfirmed client data**. No values have been invented. When confirmed values arrive, only the data function needs editing; the Sprinter 9/16/19-seat configuration wording is separate, approved copy.
